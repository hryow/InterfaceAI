# GitHub Copilot Instructions: Computer-Use Automation System

## Project Context
We are building a backend integration layer for AI agents operating inside legacy US bank/credit union software that lacks modern APIs. The target system relies on stable UIs with no test IDs, messy DOMs, or native desktop screens.

## Architecture Guidelines & Core Pillars
- **Two-Phase Architecture:** 
  1. Discovery Phase: LLM-driven "observe → decide → act" loop to complete an open-ended goal.
  2. Production Replay Phase: Purely deterministic execution using a saved artifact. The LLM must NOT be in the replay loop.
- **Robust Targeting:** Lean heavily on visual anchors, coordinate tracking, text matches, or accessibility trees rather than volatile DOM selectors.

## Error Taxonomy Constraints
When writing replay logic or result contracts, explicitly categorize and cleanly separate outcomes into these three buckets:
1. **Expected Business Outcomes:** Normal execution flows that end in non-success screens (e.g., "member not found" or "permission denied"). Treat these as legitimate results, never application crashes.
2. **Recoverable Conditions:** Transient states like loading spinners, temporary network delays, or dismissible interstitial dialogs. Code robust retry/wait polling loops for these.
3. **Hard Failures:** Automation errors where the execution path breaks entirely. Stop execution and surface a descriptive, debuggable error detailing the step, expected state, and observed state.

## Safety & Escalation Rules
- **Data Redaction:** Never persist raw credentials, access tokens, or sensitive financial PII into any logging directory, structural traces, or serialization artifacts. Redact or mask these fields automatically.
- **Human-in-the-Loop (HITL):** Implement clean seams allowing the automation to pause, yield control over the live session to a human operator when stuck or encountering an irreversible action, and resume seamlessly afterward.
